# Windows 实机测试

从成功的 [Actions 运行](https://github.com/phil616/altasci-cst/actions/workflows/windows.yml)下载测试产物，并记录运行链接或提交号。当前开发包未签名。

## 安装与启动

1. 解压 `CST-windows-x64-installer-unsigned`，用其中的 `SHA256.txt` 核对安装 EXE。运行安装器，确认默认安装到 `C:\Program Files\CST`，开始菜单快捷方式可启动。
2. 启动应用并接受管理员权限提示。确认出现主窗口，无缺少 DLL 或 Qt 插件错误；记录任何权限错误的原文。
3. 首次没有项目时应进入管理员配置界面。检查八个导航入口是否可用、文字是否截断；记录 Windows 显示缩放比例。
4. 再启动一次，确认已有窗口被激活，没有第二个主窗口。关闭后重新打开，确认可以再次启动。
5. 若只测免安装包，完整解压 `CST-windows-x64-portable-unsigned` 后运行 `cst.exe`，保留旁边的 DLL 和插件目录。

## 项目功能

使用专门的测试项目及端口。包内 `config/cst-project.example.json` 是字段示例，需要换成真实仓库、路径和命令后才能运行；不能直接作为可运行样例。

1. 在“配置 / 导入导出”导入配置，或创建项目并填写必要字段。保存、导出、重新启动后检查配置保留情况。
2. 在“维护 / 环境与凭据”配置所需环境文件、Git 用户名和 PAT；公开仓库无需保存 PAT。
3. 在“维护 / 代码同步”同步测试仓库，确认 HEAD 和文件符合远端。同步会替换目标目录中的本地修改和未跟踪文件，因此目标必须是专用部署目录。
4. 点击“一键启动”，观察准备命令、任务状态和日志。运行时管理员配置应锁定；命令启动后检查用户按钮及服务地址。
5. 分别在启动过程中和运行过程中点击停止，确认回到已停止、任务进程退出、测试端口释放。
6. 再次运行，然后直接关闭窗口，确认应用完成清理后退出，没有残留服务进程。
7. 在“诊断 / 日志”导出诊断包。请勿另行发送 PAT 或环境文件原文。
